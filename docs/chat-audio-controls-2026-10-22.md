# Chat read-aloud controls and generation queue — October 22, 2026

The learner asked to remove the automatic-playback box and reduce the delay before chat read-aloud. The old loadedmetadata handler revealed a native audio control box whenever generated audio became available, even when automatic playback succeeded. The reusable audio element now remains in a hidden host with native controls disabled. The existing Listen, Stop audio and read-aloud switch remain the visible controls. If Safari blocks automatic playback, the notice asks for another Listen tap; the prepared clip is retained and the existing synchronous cached-replay path is preserved. No audio model, preset, speaking pace, denoising steps, provider or usage limit changed.

A separate concurrency defect could add avoidable wait: different lines were posted to a single-inference worker simultaneously. The worker reports busy, and the client treated that as a voice failure and discarded the initialized engine. Generation now waits for existing jobs before posting another line. Identical lines still share one job. Queued work captures the original worker identity and checks cancellation/readiness before running, so canceled text is not sent to a replacement worker. This fixes a reproduced scheduling failure; it is not evidence that every novel line now generates in a particular number of seconds. Model startup, AI response generation and synthesis duration are separate latency sources.

AI assistance was used for investigation and implementation. Synthetic regressions first reproduced concurrent posts, then verified serialization without worker termination, shared generation, failed/aborted retry, and cancellation across worker replacement. UI assertions check hidden controls and Listen retry wording. Existing blocked-playback replay and microphone tests remain. No real microphone or private learner messages were used. Live verification and build/test evidence are appended after completion.
