# Conversation preparation and session startup — 2026-10-22

AI assistance was used to inspect and implement these changes. A previous live helper response repeated its question; suggestions now reject an exact echo after normalizing punctuation and whitespace, as well as malformed/non-Korean responses. This is a narrow safeguard, not semantic grading or proof of translation correctness. It does not silently retry or consume extra provider allowance.

The previous conversation prefetch only handled recorded/local-server audio. New generated lines therefore waited until Listen before starting browser synthesis. Visible AI replies and suggestions now prepare their audio when the existing browser engine is already ready. This neither initializes a model nor plays audio automatically. Identical in-flight synthesis requests share one worker job, and completed clips use the existing six-clip cache. Cancellation clears jobs; failed jobs can retry. Initialization, voice presets, speaking pace, model files, paid-provider guards and usage limits are unchanged. First-time model setup and generation still take time; no physical-phone or zero-latency claim is justified.

Session restoration previously fetched auth/me and then progress/me sequentially. auth/me now returns the verified account's progress in the same private/no-store response, using the same progress reader as login. No progress is queried for an unsigned visitor. The frontend strips progress from account state and supports the old response with a fallback request. Password/session verification and progress writes remain unchanged. This removes one HTTP round trip, but does not eliminate a free Render server cold start.

Focused synthetic tests cover shared generation, cancellation/retry, prefetch without initialization, echo/malformed suggestions, signed/unsigned restoration and account isolation. No real microphone, private learner prompt, analytics, billing or credentials were used or changed. Builds and live verification are recorded after completion.
