## Generated voice cache memory budget (2026-10-22)

A follow-up reliability check found that the six-clip conversation cache bounded the number of recordings, but not their combined size. The browser now retains at most six clips totaling 8 MiB. It evicts the oldest cached clip until both limits hold. A single clip above the budget can still play, but is not retained in the cache. This bounds retained generated-audio blobs only; model tensors, active playback, worker buffers and browser overhead are separate. It is not evidence of reduced physical-iPhone crashes or faster generation. Voice presets, models and provider limits are unchanged.

AI-assisted synthetic tests first reproduced three 3-MiB clips all being retained, then verified eviction and successful return of an oversized uncached clip. The existing cancellation, shared-generation and recorded-audio tests remain in place. The cache uses a simple insertion order instead of adding a new caching dependency.
