# Bubble replay and earlier speech start — October 22, 2026

The learner clarified that the partner message bubble should be the replay control, with no separate native player or Listen button beside chat messages. The Korean text, voice label and romanization are now inside a native button styled as message content. Translation/reference details remain separate controls, so opening them does not replay speech. The native button supports keyboard Enter/Space, focus indication, touch and disabled states. The reusable audio host remains hidden with native controls disabled. An already-open page must reload to receive the released JavaScript.

Previously, a novel chat line was synthesized as a complete reply before playback could begin. Browser-generated conversation audio now uses complete sentence segments, merging tiny greetings with the following sentence. The first segment is prefetched as soon as the AI response arrives; the next prepares only after playback begins, overlapping its generation with the current sentence's audio. Full recorded clips and local-server playback retain the existing path. Both typed chat read-aloud/replay and voice conversations use the same sentence playback function. Stop, failure or autoplay rejection exits the sequence; the function waits through every sentence before a voice conversation starts listening again. Different generation jobs still serialize, identical jobs share results, and voice styles, eight denoising steps, .9 base synthesis pace, user-selected pace, free-only guards and usage caps are unchanged.

Synthetic tests verify text conservation, decimal-number handling, first-sentence playback while the second prepares, same preset/pace across sentences, and Stop preventing subsequent playback. A local browser timing fixture used the actual existing Jessica engine with synthetic Korean only, after one warm-up. Generating a 50-character full reply took 6140 ms; its 24-character first sentence took 3492 ms. This single warmed desktop observation measures generation to a WAV result, not AI request latency, physical iPhone performance, or guaranteed user wait. The rest of a reply may need more total synthesis work, and slow devices can have gaps between sentences. Cold setup and the AI's own response time remain separate waits. No microphone or private learner data was used.

AI assistance was used for implementation, fixture measurement and regression tests. Final test/build/deployment observations follow after verification.
